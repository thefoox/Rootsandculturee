### Broken Flow Details

#### 1. Booking Confirmation Display (High)

**Path:** User pays for experience → webhook creates booking with confirmationCode → ConfirmationModal should show code on page.

**Break:** `checkout/page.tsx` never passes `bookings` prop to `ConfirmationModal`. The modal has the code path for displaying booking details but receives empty data. No `getBookingsByPaymentIntent()` function exists in the codebase.

**Impact:** For booking-only purchases, customers see a generic success screen but no confirmation code, experience name, or date on the page. The email confirmation IS sent correctly with all details.

**Fix:** Add `getBookingsByPaymentIntent(piId)` query and poll it alongside the order poll in ConfirmationModal.

#### 2. Customer Email in Confirmation (High)

**Path:** Customer enters email in CheckoutForm → should display in ConfirmationModal.

**Break:** `checkout/page.tsx` line 21 declares `setCustomerEmail` but it is never called. `CheckoutForm.onPaymentSuccess` callback signature is `(paymentIntentId: string)` — no email parameter. ConfirmationModal always receives `'kunde@example.com'`.

**Fix:** Extend `onPaymentSuccess` to `(paymentIntentId: string, email: string)` and thread through.
