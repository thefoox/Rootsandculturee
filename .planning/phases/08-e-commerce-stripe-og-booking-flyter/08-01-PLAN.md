<objective>
Fix the critical PaymentIntent metadata bug in the checkout flow.

**The bug:** The checkout page creates an initial PaymentIntent (PI) with `placeholder@init.no` on load. Stripe Elements binds to this PI's client secret. On form submit, `createPaymentIntent` is called again — this creates a SECOND PI with the correct customer data. But `stripe.confirmPayment()` charges the ORIGINAL PI (the one Elements is bound to), not the new one. Result: the charged PI has `placeholder@init.no` in metadata, so the webhook creates orders/bookings with no real customer email, name, or shipping address.

**The fix:**
1. Add `updatePaymentIntentMetadata` server action that calls `stripe.paymentIntents.update()` on the existing PI
2. CheckoutForm receives `paymentIntentId` prop and calls `updatePaymentIntentMetadata` on submit instead of creating a new PI
3. CheckoutPage reads the session to pass `userEmail` to CheckoutForm for pre-fill

Purpose: Orders and bookings created in Firestore must have correct customer data.
Output: Fixed checkout.ts (new action), fixed CheckoutForm.tsx (uses update not create), fixed checkout/page.tsx (passes userEmail and paymentIntentId)
</objective>
