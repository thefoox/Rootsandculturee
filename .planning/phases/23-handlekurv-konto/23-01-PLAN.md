**A) Create `src/actions/cart.ts`** — new file with `'use server'` directive.

Export `MAX_PRODUCT_QUANTITY = 99` as a named constant (used by both the server action and CartItem).

Export `CartValidationResult` interface:
```typescript
export interface CartValidationResult {
  valid: CartItem[]
  removed: Array<{
    name: string
    reason: string
    id: string
    experienceDateId: string | null
    variantId: string | null
  }>
}
```

Export `validateCartItems(items: CartItem[]): Promise<CartValidationResult>`:

- If items is empty, return `{ valid: [], removed: [] }`.
- For each item, validate based on `item.type`:

**Products (`type === 'product'`):**
1. Fetch `adminDb.collection('products').doc(item.id).get()`
2. If doc does not exist → remove with reason `"Produktet er ikke lenger tilgjengelig."`
3. If `!product.publishedAt` → remove with reason `"Produktet er ikke lenger tilgjengelig."`
4. If `item.variantId` is set, check `product.variants` array for matching variant. If variant not found → remove with reason `"Produktvarianten finnes ikke lenger."`
5. Otherwise → valid

**Experiences (`type === 'experience'`):**
1. Fetch `adminDb.collection('experiences').doc(item.id).get()`
2. If doc does not exist → remove with reason `"Opplevelsen finnes ikke lenger."`
3. Fetch `adminDb.collection('experiences/' + item.id + '/dates').doc(item.experienceDateId!).get()`
4. If date doc does not exist → remove with reason `"Opplevelsesdatoen finnes ikke lenger."`
5. If `dateData.isActive === false` → remove with reason `"Opplevelsesdatoen er ikke lenger aktiv."`
6. If `dateData.availableSeats <= 0` → remove with reason `"Opplevelsesdatoen er utsolgt."`
7. Otherwise → valid

**Gift cards (`type === 'giftcard'`):** Always valid (no server check needed).

If `adminDb` is null (build-time safety), return all items as valid with empty removed array.

Mirror the checkout.ts pattern: use `adminDb.collection(...).doc(...).get()`, check `.exists`, then `.data()`.

3. Add a `useEffect` that runs once after cart loads from localStorage:

   ```typescript
   useEffect(() => {
     if (hasValidated.current || items.length === 0) {
       setIsValidating(false)
       return
     }
     hasValidated.current = true

     validateCartItems(items).then((result) => {
       result.removed.forEach((r) => {
         removeItem(r.id, r.experienceDateId ?? undefined, r.variantId ?? undefined)
         toast.error(r.reason, { description: r.name })
       })
       setIsValidating(false)
     }).catch(() => {
       // Validation failure is non-blocking — items stay in cart, checkout will catch issues
       setIsValidating(false)
     })
   }, [items, removeItem])
   ```

   The `hasValidated` ref prevents re-running after items change due to removal. The effect fires when `items` changes from `[]` (initial) to the loaded state. `hasValidated.current = true` runs before the async call, so subsequent item-change renders skip the effect.

4. The empty cart check (`if (items.length === 0)`) should account for validation state. While `isValidating` is true and items exist, do NOT show the empty state. The current `items.length === 0` guard naturally handles this since items are only removed after validation completes.

   No visible loading indicator is needed — validation takes <500ms and items remain visible throughout. The `isValidating` state exists to prevent a flash of empty cart if all items are removed.

5. Destructure `removeItem` from `useCart()`:
