<objective>
Fix two broken cross-phase wiring issues in the checkout confirmation flow:

1. Booking confirmation details (confirmation code, experience name, date) never appear on the confirmation page after a booking-only or mixed purchase because no `getBookingsByPaymentIntent` query exists and `ConfirmationModal` never receives booking data.

2. Customer email always shows as 'kunde@example.com' in the confirmation modal because `CheckoutForm.onPaymentSuccess` does not pass the email, and `checkout/page.tsx` never calls `setCustomerEmail`.

Purpose: Close BOOK-05 (on-page booking confirmation) and PROD-06 (customer email display) gaps identified in the v1.0 milestone audit.
Output: Working confirmation flow where all purchase types show correct details and the customer's real email.
</objective>

      let cancelled = false

      async function poll() {
        while (!cancelled && attempts < maxAttempts) {
          try {
            const [orderResult, bookingResults] = await Promise.all([
              getOrderByStripePaymentIntent(paymentIntentId),
              getBookingsByPaymentIntentAction(paymentIntentId),

                  date: b.date instanceof Date ? b.date.toISOString() : String(b.date),
                  whatToBring: b.whatToBring,
                  total: b.total,
                  isEarlybird: false,
                }))
              )

            // Stop polling when we have at least one result (order or bookings)
            if (orderResult || bookingResults.length > 0) {
              setLoading(false)
              return

      return () => { cancelled = true }
