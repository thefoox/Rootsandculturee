<objective>
Deduplicate mapper functions and standardize action return types across the CMS system.

Purpose: Currently each content type has two identical mapper functions (one in `src/lib/data/*.ts` and one in `src/actions/*.ts`). This creates code drift risk. Server actions also return inconsistent shapes (`{success, errors}` vs `{success, error}` vs `Promise<void>`). This plan creates shared mappers and a unified ActionResult type.

Output: Shared mapper modules in `src/lib/mappers/`, ActionResult<T> type in `src/types/index.ts`, all consumers updated to use shared mappers.
</objective>

1. Add ActionResult types to `src/types/index.ts` after the existing AuthResult interface (around line 21). Add these two types:

```typescript
// Unified action result for CRUD mutations
export type ActionResult<T = void> =
  | { success: true } & (T extends void ? {} : { data: T })
  | { success: false; error?: string; errors?: Record<string, string> }
```

The `errors` (plural, Record) is for field-level validation errors. The `error` (singular, string) is for general errors. Both are optional because some failures are field-level and some are general.
