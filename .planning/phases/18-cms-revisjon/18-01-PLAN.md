**1. Update `firestore.rules`:**

Add rules for the three missing collections inside the `match /databases/{database}/documents` block. Keep the existing isAdmin helper pattern (inline `get()` call) consistent with other rules.

Add BEFORE the closing braces:

```
    // CMS page content — admin-only read/write (contains drafts)
    match /pageContent/{pageId} {
      allow read: if request.auth != null && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'admin';
      allow write: if request.auth != null && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'admin';
    }

    // Gift cards — admin-only (sensitive financial data)
    match /giftCards/{cardId} {
      allow read: if request.auth != null && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'admin';
      allow write: if request.auth != null && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'admin';
    }

    // Order notes — admin-only subcollection
    match /orders/{orderId}/notes/{noteId} {
      allow read: if request.auth != null && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'admin';
      allow write: if request.auth != null && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'admin';
    }
```

Also fix the articles rule OR logic (Issue 25). Replace the existing articles read rule:
```
allow read: if resource.data.publishedAt != null || (resource.data.status == 'published');
```
with:
```
allow read: if resource.data.status == 'published';
```
This ensures only articles with `status == 'published'` are client-readable, regardless of `publishedAt` field state.
