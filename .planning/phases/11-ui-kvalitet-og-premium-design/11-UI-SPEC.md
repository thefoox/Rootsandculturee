# Phase 11 — UI Design Contract

> the delta between "functional" and "$15k professional build."

## Spacing Scale

Standard 8-point scale — multiples of 4 only. These are the tokens already baked into Tailwind v4
via the @theme block. This phase enforces their consistent application; no new values are introduced.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge internal padding, tight inline spacing |
| sm | 8px | Label-to-input gap, icon-to-label gap in trust bar |
| md | 16px | Card internal padding (mobile), input padding, list item spacing |
| lg | 24px | Card internal padding (desktop), section sub-group gap |
| xl | 32px | Heading-to-content gap within a section |
| 2xl | 48px | Between-section gap (cards inside a page) |
| 3xl | 64px | Page-level section padding (currently `section-padding` = 64px desktop / 48px mobile) |

**Section vertical rhythm rule:** All top-level `<section>` elements use `py-16 md:py-24`
(64px / 96px). The existing `.section-padding` utility (64px / 96px desktop) is the canonical value.
Deviation is only permitted for hero sections (full-viewport) and trust bars (compact accent sections).

**Exceptions:**
- Hero section: `min-h-screen` — no fixed padding rule; content positioned with `pt-28` from header
- Trust bar: `py-10 md:py-14` (40px / 56px) — intentionally compact
- Footer: `py-14` (56px) — intentionally between card and section scale
- Touch targets: minimum 44px height/width on all interactive elements (WCAG 2.1 AA — existing `min-h-[44px]` on Button and Input is the floor)

## Typography

All sizes already declared as CSS custom properties in `globals.css`. This phase enforces three
refinements: letter-spacing for display/heading text, consistent measure (max-width for reading),
and Merriweather weight 300 loaded for body-adjacent uses.

| Role | Size Token | Rendered Range | Weight | Line Height | Letter Spacing |
|------|-----------|---------------|--------|-------------|----------------|
| Body | `--text-body` | 15px (fixed) | Inter 400 | 1.5 | 0 |
| Label / caption | `--text-label` | 13px (fixed) | Inter 400 | 1.5 | `0.04em` (tracking-wide) |
| Large body / lead | `--text-lg` | 17→18px (fluid) | Inter 400 | 1.65 | 0 |
| H4 / card title | `--text-h4` | 18→20px (fluid) | Merriweather 700 | 1.25 | `-0.01em` |
| H3 / section sub | `--text-h3` | 22→24px (fluid) | Merriweather 700 | 1.25 | `-0.015em` |
| H2 / section head | `--text-h2` | 28→32px (fluid) | Merriweather 700 | 1.2 | `-0.02em` |
| H1 / page title | `--text-h1` | 36→48px (fluid) | Merriweather 700 | 1.08 | `-0.025em` |
| Hero display | `--text-hero` | 44→64px (fluid) | Merriweather 700 | 1.05 | `-0.03em` |

**Phase 11 Typography refinements (not yet applied — executor must add):**

1. **Negative letter-spacing on headings:** Add `tracking-tight` (`-0.015em`) to all h2–h4 tags
   and `tracking-tighter` (`-0.025em`) to all h1/hero tags. Merriweather at large sizes benefits
   significantly from tighter tracking. Currently no tracking is set on headings.

2. **Uppercase labels:** All `text-label` instances that serve as category labels or column headings
   must have `tracking-wider` (`0.08em`) + `uppercase`. Currently applied inconsistently — some cards
   have it, footer column headings have it, trust bar does not.

3. **Body text measure:** Prose/reading sections (`TextSection`, `article-prose`, FAQ answers)
   must constrain line length to `max-w-prose` (65ch). This is missing from `TextSection` content
   and FAQ answer paragraphs.

4. **Lead paragraph pattern:** The first paragraph in any TextSection or page intro uses
   `text-lg leading-relaxed` (not just `text-body`). Currently, product page intro uses `text-body`.

5. **Merriweather 300 weight:** Load a second weight in `layout.tsx` — add `'300'` to the
   Merriweather `weight` array. This enables a premium editorial variant for hero subheadings
   (currently all Merriweather is 700 bold only). Apply as `font-heading font-light` on
   `HeroSection` subheadings and `CtaSection` subheadings over image backgrounds.

## Elevation and Shadow System

This phase introduces a three-tier elevation system. Currently the codebase uses `shadow-sm` and
`shadow-lg` inconsistently. This contract standardises it.

| Tier | Class | Applies To | Effect |
|------|-------|-----------|--------|
| 0 — Flat | no shadow | Section backgrounds, trust bar items, breadcrumbs | No shadow |
| 1 — Resting | `shadow-sm` | Cards at rest (ProductCard, ExperienceCard, category cards) | `0 1px 3px rgba(0,0,0,0.06)` |
| 2 — Hover lift | `shadow-md hover:shadow-xl hover:-translate-y-1` | Cards on hover (existing pattern, standardise) | Combined with -translate-y-1: `0 4px 24px rgba(0,0,0,0.12)` |
| 3 — Overlay | `shadow-lg` | Modals, CartDrawer, mega menu dropdown, auth modal, profile dropdown | `0 8px 32px rgba(0,0,0,0.14)` |
| 4 — Fixed overlay | `shadow-xl` | CartDrawer panel only (full-height drawer) | `0 20px 60px rgba(0,0,0,0.2)` |

**Hover lift contract:** All linked cards (ProductCard, ExperienceCard, category cards, blog cards)
must use `motion-safe:transition-all motion-safe:duration-200 hover:shadow-md hover:-translate-y-1`.
Currently ProductCard uses `duration-150` and `hover:shadow-xl` (too heavy). ExperienceCard uses
`hover:shadow-lg`. Standardise to `hover:shadow-md` for tier-2. `hover:shadow-xl` is tier-4 only.

**Border contract:**
- Cards: `border border-forest/8` (existing — keep)
- Inputs: `border border-forest/20` at rest, `border-forest` on focus (existing — keep)
- Section dividers: `border-t border-forest/10` (existing footer pattern — apply consistently)
- Mega menu dropdown: `border border-forest/15` (existing — keep)

## Motion System

**Existing guard:** Transitions are OFF by default via `animation-duration: 0ms; transition-duration: 0ms` in globals.css. Enabled only under `prefers-reduced-motion: no-preference`. All new animations must use `motion-safe:` Tailwind modifier or be inside the `@media (prefers-reduced-motion: no-preference)` block.

### Duration Scale

| Duration | Value | Usage |
|----------|-------|-------|
| instant | 100ms | Button active state, checkbox toggles, small state flips |
| fast | 150ms | Nav link hover underline, icon color transitions |
| standard | 200ms | Card hover lift + shadow, mega menu open/close, input border color on focus |
| medium | 300ms | Image zoom on card hover (`group-hover:scale-105`), CartDrawer slide-in |
| slow | 500ms | Page section fade-in on scroll reveal (new — see below) |
| bounce | `animate-bounce` | Hero scroll indicator (existing ChevronDown — keep) |

### Easing

| Context | Easing | CSS |
|---------|--------|-----|
| All hover transitions | ease-out | `transition-timing-function: cubic-bezier(0.0, 0.0, 0.2, 1)` |
| Slide-in drawers | ease-out | Same as above |
| Bounce (scroll indicator) | default bounce | Tailwind `animate-bounce` |
| Scale-down on active | ease-in | `active:scale-[0.98]` existing pattern |

### New Animations for Phase 11

**1. Scroll reveal (fade-up on enter):**
Apply to: section headings, trust bar items, card grids as a group (not individual cards — too busy).
Implementation: `IntersectionObserver` with a reusable `useScrollReveal` hook or a `ScrollReveal`
wrapper Client Component. Transition: `opacity 0 → 1` + `translateY(16px) → translateY(0)` over
500ms ease-out. Threshold: 0.15 (trigger when 15% visible). Add `will-change: transform, opacity`
only while animating — remove after animation completes via `animationend`.
Must be wrapped in `motion-safe` — if user prefers reduced motion, elements render immediately visible.

**2. Header scroll transition (sticky + compact):**
When page scrolls > 80px on non-hero pages, header transitions from `bg-cream/95 backdrop-blur-md`
to `bg-cream shadow-md`. On hero pages, header transitions from transparent/cream-text to
`bg-forest` (full opaque forest green). Duration: 200ms ease-out. Use `useScrollPosition` hook
reading `window.scrollY` in a `useEffect` with `{ passive: true }` scroll listener.
Currently: header is `absolute` with no scroll-aware sticky state. This is the biggest premium-feel gap.

**3. Image zoom standardisation:**
All card images already have `group-hover:scale-105 motion-safe:transition-transform motion-safe:duration-300`.
Add `motion-safe:duration-400` to hero section images for a slower, more editorial feel.
Add `overflow-hidden` guard to all image containers (confirm existing coverage — some cards
in `ProductsGridSection` may be missing it).

**4. Mega menu fade-in:**
Already implemented via `animate-[fadeInDown_200ms_ease-out]`. Keep as-is.

**5. Cart drawer slide-in:**
Already implemented via `animate-slide-in-right 200ms ease-out`. Keep as-is.

**6. FAQ accordion expand:**
Currently uses native `<details>/<summary>` with `+` rotate. Replace `+` character with a
lucide `Plus` / `Minus` icon swap. The chevron rotation (`group-open:rotate-45`) is functional
but not premium. Add `motion-safe:transition-[max-height] motion-safe:duration-200` to the answer
paragraph — this requires converting `<details>` to a controlled component if smooth height
animation is desired. Minimum acceptable: keep `<details>` but upgrade the icon.

## Form Styling

### Input Component (`Input.tsx`)

Current state: `min-h-[44px] rounded-md border bg-card px-3 py-2`. Functional, not premium.

Phase 11 refinements:

1. **Padding:** Increase to `px-4 py-3` (currently `px-3 py-2`). The extra space makes inputs

2. **Border radius:** Change from `rounded-md` to `rounded-lg` for a softer, more modern feel.

3. **Focus state:** Currently `focus:border-forest`. Add `focus:ring-2 focus:ring-forest/15`

4. **Label typography:** Change from `font-normal tracking-wide` to `font-medium tracking-wide`.
   Medium weight (500) for labels is more premium than 400.

5. **Error state:** Currently just `border-destructive`. Add `bg-destructive/5` to the input

6. **Placeholder:** Keep `placeholder:text-body/60` — correct contrast ratio.

4. **Transition:** Change from `transition-all duration-100` to `motion-safe:transition-all

## Section-Level Background Texture

This phase adds one subtle texture to reinforce the nature brand — applied sparingly.

**Texture: subtle grain overlay on hero sections only.**

Implementation: CSS pseudo-element on the `HeroSection` and `CtaSection` (with image variant):
```css
.hero-texture::after {
  content: '';
  position: absolute;
  inset: 0;
  background-image: url("data:image/svg+xml,...");  /* 64x64 SVG noise pattern */
  opacity: 0.04;
  pointer-events: none;
  z-index: 1;
}
```
Use a 64×64 SVG turbulence noise pattern at 4% opacity. This adds a photographic film-grain
quality without being perceptible to most users — it only reads subconsciously as texture.

Do NOT apply texture to:
- Card backgrounds
- Form areas
- Footer
- Any non-image-backed section
