**Fix gift card discount not applied to Stripe PaymentIntent amount**

In `src/actions/checkout.ts`, the `updatePaymentIntentMetadata` function (lines 253-436) calculates `giftCardDeduction` and stores it in metadata but never updates the PI `amount`. The customer is charged the full price AND the gift card balance is deducted — double-charging.

**Fix:** After calculating `giftCardDeduction` in `updatePaymentIntentMetadata` (around line 368), if `giftCardDeduction > 0`, update the PI amount alongside the metadata:

```typescript
// In the stripe.paymentIntents.update call (line 382), add amount:
const newTotal = total > 0 ? total : subtotal + shippingCost
await stripe.paymentIntents.update(paymentIntentId, {
  amount: newTotal,  // <-- ADD THIS LINE
  metadata: { ... }
})
```

Also handle the `coveredByGiftCard` case: if `total <= 0` after gift card deduction, the entire order is covered by gift card. Return a specific response instead of trying to update a PI with amount 0 (Stripe rejects amount < 50 for NOK). This means:

1. In `updatePaymentIntentMetadata`, after calculating `total = subtotal + shippingCost - giftCardDeduction`:
   - If `total <= 0`: cancel the existing PI via `stripe.paymentIntents.cancel(paymentIntentId)`, then call `redeemGiftCard` and create the order/bookings directly (fulfillment without Stripe payment), return `{ coveredByGiftCard: true }`
   - If `total > 0`: update PI with new `amount: total` + metadata

2. In `CheckoutForm.tsx`, handle the `coveredByGiftCard` response from `updatePaymentIntentMetadata`:
   - If response has `coveredByGiftCard: true`, skip `stripe.confirmPayment()` and call `onPaymentSuccess` directly

**Verification:** `npm run build` passes. The `updatePaymentIntentMetadata` function includes `amount` in the update call. Gift card deduction > 0 reduces the charged amount.
</task>

<task id="2" type="code" effort="S">
**Fix variant stock not decremented in webhook**

In `src/app/api/webhooks/stripe/route.ts` (lines 170-183), stock decrement only updates `product.stockCount` but ignores `variantId`. When a variant product is purchased, the specific variant's stock should also be decremented.

**Fix:** In the stock decrement loop, check if the item has a `variantId`. If so, update the specific variant's stockCount in the `variants` array:

```typescript
for (const item of orderItems) {
  const productRef = adminDb.collection('products').doc(item.productId)
  await adminDb.runTransaction(async (transaction) => {
    const productDoc = await transaction.get(productRef)
    if (!productDoc.exists) return
    const data = productDoc.data()!
    const currentStock = data.stockCount ?? 0
    const newStock = Math.max(0, currentStock - item.quantity)
    const updates: Record<string, unknown> = {
      stockCount: newStock,
      inStock: newStock > 0,
    }
    // Also decrement variant stock if variantId present
    if (item.variantId && Array.isArray(data.variants)) {
      const variants = data.variants.map((v: { id: string; stockCount: number }) => {
        if (v.id === item.variantId) {
          const newVariantStock = Math.max(0, (v.stockCount ?? 0) - item.quantity)
          return { ...v, stockCount: newVariantStock }
        }
        return v
      })
      updates.variants = variants
    }
    transaction.update(productRef, updates)
  })
}
```

The `item.variantId` is available in the metadata (set at line 393 of checkout.ts).

**Verification:** `npm run build` passes. The webhook handler reads `variantId` from orderItems metadata and decrements both product-level and variant-level stock.
</task>

**Fix Google login CSP — add apis.google.com to connect-src**

In `next.config.ts` (line 30), the CSP `connect-src` is missing `https://apis.google.com`. The existing wildcard `https://*.googleapis.com` does NOT cover `apis.google.com` (different domain, not a subdomain).

**Fix:** Add `https://apis.google.com` to `connect-src`. Also add `https://*.google.com` to `frame-src` for robustness with different Google account types:

```
connect-src 'self' https://api.stripe.com ... https://apis.google.com;
frame-src https://js.stripe.com https://hooks.stripe.com https://*.firebaseapp.com https://accounts.google.com https://*.google.com;
```

**Verification:** `npm run build` passes. CSP header in next.config.ts includes both additions.
</task>

<task id="4" type="code" effort="S">
**Fix session module build-time crash**

In `src/lib/session.ts` (lines 6-9), `if (!secretKey) { throw new Error(...) }` at module evaluation time crashes the Next.js build if `SESSION_SECRET` is not set. This should be deferred to runtime.

**Fix:** Remove the module-scope throw. Instead, make `encodedKey` lazy — compute it on first use:

```typescript
const secretKey = process.env.SESSION_SECRET
let _encodedKey: Uint8Array | null = null
function getEncodedKey(): Uint8Array {
  if (!_encodedKey) {
    if (!secretKey) {
      throw new Error('SESSION_SECRET environment variable is required.')
    }
    _encodedKey = new TextEncoder().encode(secretKey)
  }
  return _encodedKey
}
```

Then replace all references to `encodedKey` with `getEncodedKey()` in `createSession` and `verifySession`.

**Verification:** `npm run build` passes even without SESSION_SECRET set. Runtime calls to session functions still throw if SECRET is missing.
</task>
