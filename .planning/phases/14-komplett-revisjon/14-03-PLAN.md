<task id="1" type="code" effort="M">
**Fix refund webhook to restore booking seats**

In `src/app/api/webhooks/stripe/route.ts` (lines 401-433), the `charge.refunded` handler finds the order and marks it `cancelled`, but does NOT look up associated bookings or restore seat counts.

**Fix:** After updating the order status, also check for bookings associated with the same paymentIntentId:

```typescript
// After updating order status (existing code)...

// Also restore booking seats if this payment had bookings
const bookingsSnapshot = await adminDb!
  .collection('bookings')
  .where('stripePaymentIntentId', '==', paymentIntentId)
  .get()

for (const bookingDoc of bookingsSnapshot.docs) {
  const booking = bookingDoc.data()
  if (booking.status === 'confirmed' && booking.experienceDateId) {
    // Restore seats atomically
    const dateRef = adminDb!
      .collection('experiences')
      .doc(booking.experienceId)
      .collection('dates')
      .doc(booking.experienceDateId)
    
    await adminDb!.runTransaction(async (transaction) => {
      const dateDoc = await transaction.get(dateRef)
      if (!dateDoc.exists) return
      const dateData = dateDoc.data()!
      transaction.update(dateRef, {
        bookedSeats: Math.max(0, (dateData.bookedSeats ?? 0) - booking.numberOfGuests),
        availableSeats: (dateData.availableSeats ?? 0) + booking.numberOfGuests,
      })
    })

    // Mark booking as cancelled
    await bookingDoc.ref.update({ status: 'cancelled' })
  }
}
```

Check the booking document schema to confirm field names (`stripePaymentIntentId`, `experienceId`, `experienceDateId`, `numberOfGuests`, `status`). Read `src/actions/bookings.ts` for the cancel booking logic already implemented — mirror that transaction pattern.

**Verification:** `npm run build` passes. The `charge.refunded` handler queries bookings and restores seats.
</task>
