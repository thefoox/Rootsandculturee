# Phase 17 — UI Design Contract

> Visual and interaction contract for the checkout redesign. Generated by gsd-ui-researcher.
> This is a visual redesign only — all existing functionality and component structure is preserved.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Tailwind v4 CSS-native tokens |
| Preset | not applicable |
| Component library | none — custom Tailwind primitives |
| Icon library | lucide-react (already in use) |
| Font heading | Merriweather (serif) — var(--font-heading) |
| Font body | Inter (sans-serif) — var(--font-body) |

Source: `src/app/globals.css` @theme block, `CLAUDE.md` tech stack.

shadcn is explicitly noted as "not chosen" in CLAUDE.md: "For a brand-specific design (dark green + autumn), starting from Tailwind primitives gives more control."

## Spacing Scale

Standard 8-point scale mapped to Tailwind utilities:

| Token | Value | Tailwind | Usage in this phase |
|-------|-------|----------|---------------------|
| xs | 4px | gap-1 | Icon-to-label gaps, badge padding |
| sm | 8px | gap-2 / p-2 | Inline element spacing |
| md | 16px | gap-4 / p-4 | Form field gap, card inner padding (compact) |
| lg | 24px | gap-6 / p-6 | Card inner padding (standard), section gap |
| xl | 32px | gap-8 / mb-8 | Between form sections |
| 2xl | 48px | pt-12 | Page top padding |
| 3xl | 64px | pb-16 | Page bottom padding |

Exceptions:
- Step indicator circles: 40px (10 Tailwind units) — larger than current 32px for premium feel, still within 8-point scale
- Touch targets minimum: 44px height on all interactive elements (WCAG 2.1 AA) — already enforced by Button (min-h-[44px]) and Input (min-h-[44px])
- Page max-width: 960px (up from 900px) — gives the layout more breathing room
- Left column width: 58% on desktop — right column: 42%
- Column gap: 48px (gap-12) — existing, keep

## Typography

All sizes use existing @theme tokens from globals.css. No new sizes added.

Exactly 2 font weights are used across this phase: **400 regular** and **700 bold**.

| Role | Token | Size | Weight | Line Height | Font | Usage |
|------|-------|------|--------|-------------|------|-------|
| Page heading | --text-h2 | clamp(28→32px) | 700 bold | 1.1 (tight) | Merriweather | "Kasse" page title |
| Section heading | --text-h4 | clamp(18→20px) | 700 bold | 1.25 (snug) | Merriweather | "Kontaktinformasjon", "Leveringsadresse", "Betaling", "Sammendrag" |
| Body | --text-body | 15px | 400 regular | 1.5 (normal) | Inter | Form field values, summary line items, descriptions |
| Label | --text-label | 13px | 400 regular | 1.5 | Inter | Field labels, step names, meta text (code, address details) |

Typography changes from current:
- Page title ("Kasse"): add letter-spacing: -0.02em for premium feel
- Section headings: add letter-spacing: -0.015em (matches article-prose pattern already in globals.css)
- Summary "Totalt" line: label uses font-bold weight 700 and price uses font-bold weight 700 — both in --color-forest, creating clear hierarchy via size not weight variation
- Step indicator labels ("Kontaktinfo", "Betaling"): 13px label weight 400 (font-normal), body color — not 60% opacity

Weight mapping for executor (all class replacements):
- `font-medium` (500) → `font-normal` (400) everywhere in this phase
- `font-semibold` (600) → `font-bold` (700) everywhere in this phase

## Component Contracts

### CheckoutPage (`src/app/(public)/checkout/page.tsx`)

**Layout changes:**
- `max-w-[900px]` → `max-w-[960px]`
- `pt-24 pb-16` → `pt-12 pb-20` (less top padding — page heading creates natural space)
- Page heading `mb-8` → `mb-10`
- Column gap: keep `gap-12`
- Left column: `flex-1` with `lg:max-w-[58%]`
- Right column: `lg:w-[42%]`

**GiftCardInput placement:** Move BELOW the CheckoutForm wrapper, not above. It currently sits at the top of the left column before the form loads. New position: after the form container, still within the left column, rendered only when clientSecret is available. This way gift card feels like an extension of the checkout flow, not a pre-form widget.

**Loading state:** Replace `<p className="text-body">Laster betalingsskjema...</p>` with a structured skeleton:
- Two 44px-height skeleton bars (rounded-lg, bg-card, animate-shimmer) representing field placeholders
- One 48px skeleton bar for the CTA area
- Use existing `.animate-shimmer` class from globals.css

**Mobile summary accordion:** Change `<summary>` from plain rounded-lg to include a ChevronDown icon (lucide-react) that rotates 180deg when open (motion-safe). Summary text: "Vis ordresammendrag" stays. Price display in the summary trigger: keep `(formatPrice(total))`.

## Interaction Contracts

### Step progression
- Step 1 → Step 2: validate all fields, show inline errors via existing FormError pattern
- No animation needed on step transition beyond the progress connector fill (existing motion-safe:transition-all duration-300)
- On step 2, scroll to top of the form container (`scrollIntoView({ behavior: 'smooth', block: 'start' })`) after step advance — currently missing

### Focus management
- After clicking "Gå til betaling" and advancing to step 2: move focus to the step 2 heading (`<h2>Betaling</h2>`) via `ref.current?.focus()` with `tabIndex={-1}`
- On validation error: focus the first errored field
- Both are WCAG 2.1 AA requirements for multi-step forms

### Gift card disclosure toggle
- `aria-expanded="true/false"` on the trigger button
- `aria-controls` pointing to the expandable panel id
- ChevronDown icon: `motion-safe:transition-transform motion-safe:duration-200` rotate-180 when expanded

### Mobile summary accordion
- `<details>` element preserved for native browser behavior
- Add `aria-label="Ordresammendrag"` to the `<details>` element
- ChevronDown icon in the `<summary>` rotates via `details[open] .chevron { transform: rotate(180deg) }`

### Payment loading state
- Button shows spinner (existing Loader2 pattern in Button component)
- Text changes to "Behandler betaling..." (already implemented)
- Entire form is non-interactive while loading (disabled prop already on button; add `pointer-events-none opacity-60` to the PaymentElement container during loading)

### Error states
- Payment error: existing FormError component placement below PaymentElement is correct — keep
- Init error: existing `bg-destructive/10 text-destructive` banner is correct — keep
- Field validation errors: shown inline below each field via existing Input error prop — keep

## Accessibility Contract

All requirements from WCAG 2.1 AA (Norwegian legal requirement).

| Requirement | Implementation |
|------------|----------------|
| Focus rings | Existing `*:focus-visible` in globals.css — 2px forest outline |
| Touch targets | All interactive elements min 44px height — enforced in Button and Input |
| Form labels | Every input has `<label>` via Input component — keep |
| aria-live regions | Payment error uses `role="alert"` via FormError — keep |
| Keyboard navigation | All interactive elements reachable via Tab — no div-onClick patterns |
| Step indicator | Numbers + labels — screen reader reads "1 Kontaktinfo" then "2 Betaling" |
| Completed step icon | Check icon must have `aria-hidden="true"`, circle must have `aria-label="Fullført"` |
| Color contrast | forest (#1B4332) on cream (#FEFCF3): 8.5:1 — passes AA |
| Color contrast | body (#374740) on card (#F5F0E8): ~6.2:1 — passes AA |
| Color contrast | destructive (#6B3A2A) on card (#F5F0E8): ~5.1:1 — passes AA |
| Motion | All transitions inside `motion-safe:` modifier or `prefers-reduced-motion: no-preference` block |
| Disclosure pattern | Gift card toggle: `aria-expanded` + `aria-controls` |
| Multi-step focus | Move focus to step 2 heading on advance |
